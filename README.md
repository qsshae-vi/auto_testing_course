# Домашнее задание №6. Применение паттернов проектирования в UI-автотестах

Продолжение проекта по автоматизированному UI-тестированию социальной сети [Одноклассники](https://ok.ru/).

## Технологии

- Java 17
- Maven
- Playwright Java 1.58.0
- JUnit 5
- Allure Report

## Подготовка окружения

Для запуска тестов необходимы JDK 17 и Maven.

Установить зависимости проекта:

```bash
mvn clean test-compile
```

## Настройка авторизации

Для выполнения тестов необходима авторизация в Одноклассниках. Состояние авторизованной сессии сохраняется с помощью Playwright Codegen.

**1. Создать директорию для данных авторизации**

```powershell
New-Item -ItemType Directory -Force playwright/.auth
```

**2. Запустить Playwright Codegen**

```powershell
mvn exec:java "-Dexec.mainClass=com.microsoft.playwright.CLI" "-Dexec.classpathScope=test" "-Dexec.args=codegen --save-storage=playwright/.auth/user.json https://ok.ru"
```

**3. Авторизоваться**

В открывшемся браузере войти в аккаунт Одноклассников.

**4. Сохранить состояние сессии**

Закрыть окно браузера Codegen после успешной авторизации.

Состояние сессии будет сохранено в `playwright/.auth/user.json`.

**5. Вступить в тестируемую группу**

Для создания публикаций необходимо быть участником [тестируемой группы](https://ok.ru/group/70000060453292).

## Реализованные паттерны

### 1. Page Object

**Класс:** `pages/GroupPage.java`

Инкапсулирует локаторы и действия со страницей группы: получение заголовка, открытие редактора новой темы, поиск публикации и получение компонента черновика.

### 2. Page Component (Page Element)

**Классы:**
- `components/TopicEditorOverlay.java`
- `components/PostComponent.java`
- `components/DraftComponent.java`

Отдельные элементы интерфейса представлены самостоятельными классами.

`TopicEditorOverlay` отвечает за взаимодействие с редактором темы, `PostComponent` - за работу с конкретной публикацией, `DraftComponent` - за сохранённый черновик.

Для поиска элементов публикации используется корневой локатор `root`, ограничивающий область поиска конкретным постом.

### 3. Loadable Component

**Классы:**
- `core/LoadableComponent.java`
- `pages/GroupPage.java`

Реализован абстрактный класс `LoadableComponent`, задающий общий алгоритм загрузки страницы.

Методы:
- `load()` - выполняет переход на страницу;
- `isLoaded()` - проверяет, открыта ли нужная страница;
- `waitUntilLoaded()` - ожидает появления элемента, подтверждающего готовность страницы;
- `get()` - вызывает загрузку и ожидает готовности.

`GroupPage` наследуется от `LoadableComponent` и переопределяет абстрактные методы.

В тестах для открытия страницы используется `groupPage.get()`.

### 4. Value Object

**Класс:** `model/TopicText.java`

Для представления текста тестовой публикации используется неизменяемый Java `record`: cодержит текст темы, проверяет его корректность и предоставляет статический метод `random()` для генерации уникальных значений с использованием UUID.

### 5. Chain of Invocations

**Классы:** `TopicEditorOverlay.java`, `DraftComponent.java`, `DraftFlow.java`

Реализована возможность последовательного вызова методов, при которой результат одного метода используется для вызова следующего.

Пример удаления черновика:

```java
draft.open().clearDraft().closeEditor();
```

`DraftComponent.open()` возвращает объект `TopicEditorOverlay`, а `clearDraft()` возвращает текущий объект редактора.

### 6. Facade 

Метод `clearIfNeeded()` проверяет состояние редактора, наличие черновика и при необходимости выполняет его удаление.

Позволяет исключить дублирование логики очистки черновика в `GroupPostTest` и `TopicPublishingTest`.

### 7. Data Provider

**Класс:** `data/TopicTextDataProvider.java`

Наборы тестовых данных для проверки ввода текста вынесены из тестового класса в отдельный поставщик данных.

В параметризованных тестах JUnit 5 данные передаются с использованием `@MethodSource`.

Это позволяет отделить тестовые данные от логики тестирования и добавлять новые варианты ввода без изменения тестового сценария.

## Реализованные тесты

1. Открытие страницы группы и проверка отображения заголовка.
2. Открытие редактора новой темы.
3. Проверка отображения и доступности поля ввода.
4. Ввод текста в редактор с использованием параметризованных тестов (обычный текст, цифры, специальные символы).
5. Очистка введённого в редакторе поста текста.
6. Проверка недоступности публикации при пустом поле ввода.
7. Публикация текстовой темы в группе.
8. Проверка появления опубликованного поста в ленте.
9. Удаление тестовой публикации.
10. Очистка сохранённых черновиков.

## Запуск тестов

Запуск всех тестов:

```bash
mvn clean test
```

Запуск отдельного класса:

```bash
mvn -Dtest=GroupPostTest test
```

```bash
mvn -Dtest=TopicPublishingTest test
```

## Отчётность Allure

После выполнения тестов сформировать и открыть отчёт:

```bash
mvn allure:serve
```
